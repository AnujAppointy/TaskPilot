# Semantic Repo Memory Plan

## Summary
The current checkpoint system records safe file-level memory, but not rich intent. We will add a semantic memory layer that prefers agent-authored summaries, then uses a local privacy-safe diff summary fallback, and only falls back to plain file checkpoints when nothing better is available.

## Key Changes

- Add a structured semantic memory contract for agents.
  - Update repo hook context to require this shape after meaningful work: completed work, why it changed, files touched, verification, remaining work.
  - Add MCP tool `record_repo_semantic_memory` that accepts those fields instead of one free-form string.
  - Store the final combined memory as a normal `summary` context entry with `source=agent-hook|mcp`, `reason=semantic_memory`, and related files.

- Add a local semantic draft command.
  - New command: `taskpilot context draft-summary --repo . --format markdown|json`.
  - It reads only safe local metadata by default: changed product files, git status, diff stats, file additions/deletions, markdown headings, filenames, and existing TaskPilot task context.
  - It must not upload raw code or full file contents.
  - Example output: `Added futurescope.md with future enhancements covering difficulty modes, pause/resume, high score, touch controls, visual polish, and configurable board sizes.`

- Upgrade checkpoint to use semantic drafts.
  - `taskpilot context checkpoint` should call the draft-summary logic first.
  - If a semantic draft exists, checkpoint stores that instead of `Added futurescope.md and recorded the repo work checkpoint`.
  - If only low-confidence metadata exists, checkpoint falls back to the current file-based summary.

- Add confidence and source labeling.
  - Context metadata should include optional `confidence`: `agent_authored`, `metadata_inferred`, or `file_checkpoint`.
  - UI should show this subtly so users know whether memory came from agent reasoning or local inference.
  - Render agent-authored memory before metadata-inferred memory.

- Add agent-end guidance.
  - Session-end hook still runs `taskpilot context checkpoint`.
  - Startup context should instruct capable agents to call `record_repo_semantic_memory` before the session ends.
  - Daemon fallback uses `draft-summary`, but only when no agent-authored memory exists for the same changed files.

## Safe Metadata Rules

- Allowed by default:
  - Git status and changed file paths.
  - `git diff --numstat` and `--shortstat`.
  - Markdown headings and first-level section names from changed `.md` files.
  - Package/module/function names only if easy to extract without sending full bodies.

- Not allowed by default:
  - Raw source file contents.
  - Full diffs.
  - Secrets, logs, screenshots, prompts, customer data.
  - External LLM calls.

- Optional future mode:
  - Add `--include-diff` or server-side AI summarization later, but only behind explicit opt-in.

## Test Plan

- Semantic draft tests:
  - New markdown file with headings produces a meaningful summary.
  - Multiple changed files produce a compact combined summary.
  - TaskPilot-managed files are ignored.
  - No changed product files returns a no-op draft.

- Checkpoint tests:
  - Semantic draft replaces plain file checkpoint when available.
  - Agent-authored memory prevents daemon duplicate memory.
  - File checkpoint fallback still works when metadata is too weak.

- MCP/API tests:
  - `record_repo_semantic_memory` validates required fields and records context with files/source/reason.
  - UI recent memory displays source and confidence correctly.

- Privacy tests:
  - Draft summary does not include raw source lines.
  - Secret-looking values are redacted if encountered in headings or filenames.

## Assumptions

- Default implementation should stay privacy-first and local-only.
- Richest memory should come from the agent that did the work.
- Metadata inference is a helpful fallback, not the source of truth.
- External AI summarization should not be added until explicitly opted in.
